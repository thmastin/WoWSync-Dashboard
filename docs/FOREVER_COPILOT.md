# Forever Co-Pilot

A goal-aware, read-only advisor for WoW Forever. A player asks a question ("What should Rordin do to
improve?", "How can my stable make gold?") and gets ranked recommendations built from the account's
Forever evidence plus Forever game knowledge, each with provenance, prerequisites, costs, tradeoffs,
unknowns and next actions.

## Surfaces

| Surface | How |
| --- | --- |
| MCP | `ask_forever_copilot` (read-only). `format: "markdown"` returns the compact player answer. |
| REST | `POST /api/versions/forever/copilot` with `{ question, character?, realm?, objectives?, preferences?, limit? }`. Other versions return 422. |
| Dashboard | Forever tab, **Co-Pilot** button in the header. |

## How an answer is built

`packages/core/src/foreverCopilot.ts` (`answerForeverCopilot`):

1. **Objective.** Words in the question map to `IMPROVE_CHARACTER`, `GEAR`, `LEVELING`,
   `DEVELOP_PROFESSIONS`, `SELF_SUFFICIENCY`, `MAKE_GOLD`. "Improve" deliberately implies gear,
   leveling and professions. Callers can pass `objectives` and `preferences.emphasis`
   (`IMMEDIATE_POWER`, `SELF_SUFFICIENCY`, `BALANCED`), `avoidSpending`, and extra `goals`.
2. **Subject and scope.** A named character (unique, or disambiguated by realm) scopes the answer to
   that realm. Stable questions are answered per realm; realms never share materials, gold or mail.
3. **Evidence.** Only `DashboardReadModel` reads with version `forever`: state, equipment, bags,
   bank, professions, learned recipes, spellbook, quests, ERP projects.
4. **Candidates** from several generators: owned gear in bags, unbound gear on same-realm
   same-faction characters, quest turn-ins and open quests (XP/coin/rep from Forever data), learned
   recipes (gear upgrades and weapon enhancements, reagent chains such as ore -> smelt -> bar),
   missing profession tools, well-fed food on the realm, First Aid from owned cloth, the gold
   bottleneck; for goldmaking: vendor floors for grey items, material conversions valued at Forever
   vendor prices, gathering capacity, routing tradeable gear to the character it improves (holder
   first), resource allocation to crafters, and recipe-capture evidence gaps.
5. **Comparison.** Item stats come from the Forever knowledge dataset. A candidate is an UPGRADE
   only if no listed stat is worse; otherwise TRADEOFF with the losses listed (two-handers also lose
   the off-hand). It compares listed stats, not a simulation.
6. **Ranking.** `0.45 x value + 0.35 x feasibility + 0.20 x objective fit`, reduced by a cost
   penalty (gold cost vs observed gold; unknown costs carry a small penalty). Each recommendation
   states its score basis.
7. **Challenges.** The answer pushes back where evidence supports it: better items already owned,
   recipes whose output is already owned, beta gold expected to be wiped, no market prices.

Goldmaking recommendations carry a bucket: `SUPPORTED_NOW`, `NEEDS_INPUTS_OR_PROGRESSION`,
`MARKET_DEPENDENT`.

## Provenance rules

Every evidence line is `OBSERVED`, `DERIVED`, `LAST_SEEN`, `EXTERNAL` or `UNKNOWN`. LAST_SEEN bank
contents say "last seen ... not confirmed current". Unknown banks, trainers, talents, reputation,
station locations and Auction House prices are listed under limitations. No price, ownership,
recipe, eligibility or mechanic is invented. Weapon skills and unworn armor types become explicit
prerequisites. The co-pilot never moves items: every transfer step says the player runs it.

## Forever game knowledge

`packages/core/src/foreverKnowledge.ts` holds parsers, lookups and a short list of curated system
facts with confidence labels (`OFFICIAL`, `DATABASE`, `SECONDARY_GUIDES`, `INFERRED_FROM_PRECEDENT`).
`packages/core/src/foreverKnowledgeData.ts` is generated by:

```
node tools/forever-knowledge/refresh.ts --db <path to a wowsync.sqlite>   # add --force to refetch
```

It opens the database read-only, collects the item, recipe-spell and quest IDs the account has
actually observed (plus a few profession tools/inputs), and fetches only Wowhead's `/forever/` data
environment (`nether.wowhead.com/forever/tooltip/...` and quest pages). Stored: item level, slot,
type, armor, damage/DPS, stats, required level, binding, use text, vendor sell price; recipe tools
and reagents; quest XP/coin/reputation/reward items and vendor buy prices for referenced items.
Never stored: Wowhead `avgbuyout` (not a Forever market price). The number Wowhead prints after a
created item is kept as `createsMarker` and never used as yield.

Cross-check at creation: Copper Bracers 35 Armor and Rough Copper Vest 108 Armor + 1 Stamina match
the client's own `GetItemStats` observations.

## Reuse decisions (2026-10-12)

| Candidate | Decision |
| --- | --- |
| Wowhead Forever database | Used. Forever-specific, covers every ID the account holds, values match client observations. |
| Questie (QuestieDB Forever branch, GPLv3) | Not used yet. Main Questie tracker does not list quests on Forever; the Forever DB branch is the best future source for quest locations/objectives. Licensing must be checked before vendoring data. |
| Pawn | Not used. Its stat-weight scales are not validated for Forever; the co-pilot uses dominance comparison instead of invented weights. |
| AtlasLoot, Altoholic/DataStore | Not used. Item sources come from Wowhead Forever; account tracking already exists in GearExport/Dashboard. |
| Auctionator / Auctioneer / TradeSkillMaster | Not used. No Forever market data reaches WoWSync; prices stay UNKNOWN. A future GearExport capture of Auctionator scan data would be the route. |
| LibStub/Ace3/LibDataBroker | Not relevant: no addon change in this slice. |

## Known limits

- Recipe knowledge exists only for characters whose profession window was captured; others get a
  "capture recipes" action.
- Class trainer offers/costs, talents, reputation standings, quest-giver locations, crafting
  stations and mail postage are not known.
- Objective detection is keyword-based.
