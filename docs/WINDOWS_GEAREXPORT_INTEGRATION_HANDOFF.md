## GearExport items (robustness; contracts exist)

- **G-C1 — Classic progression interface gate.** `WoWSyncClassicProgression.lua` `profile()` returns nil
  unless the interface is exactly `11509` or `20506`, so quests, reputation, and talents are silently absent on
  any other Era/TBC patch. Recipes use any positive interface. Confirm the live interface numbers (W2.4). If they
  differ, apply the same policy as `FOREVER_UPDATE_RESILIENCE.md`: identify the family by project ID and interface
  family, keep the exact interface as provenance, and leave each API guard in place. The Dashboard already accepts
  any `Classic:<project>:<1xxxx|2xxxx>` profile and checks the family against the export's own version.
- **G-C2 — Hardcore / Self-Found ruleset is not exported.** Hardcore and SSF realms route to `classic-era` by
  client version. Their identities stay separate because realm names differ, but the Dashboard cannot apply
  ruleset constraints (e.g. SSF trade restrictions) because no ruleset field exists. If this matters, propose a
  field in GearExport first: candidate client APIs must be verified in game before any schema is written. The
  Dashboard will not infer a ruleset from realm names.
