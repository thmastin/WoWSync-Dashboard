## Phase 49 player workflow

Open **Projects & Work Orders** for an active version, choose **Build grouped review** when at least two requirements have no current linked task, select up to four, optionally assign a same-version reviewer and open prerequisites, then create the review. The task retains each linked need and its evidence snapshot. The player must reopen linked needs after new imports before deciding whether to reserve, retrieve, craft, gather, procure, or leave them unresolved.

This workflow was exercised with synthetic data in a disposable SQLite database and a headless browser. It has not been live-game or production-validated.

## Phase 56-57 player workflow

Open **Projects & Work Orders** for an explicit version, select requirement rows from active projects, choose a manual work type, enter instructions, and optionally assign a character observed in that same version. For an INVESTIGATE task, a currently matching same-version observed candidate may be recorded as a separate source lead. The existing requirement source remains intact; the work-order detail says the lead was a location match when planned and must be rechecked. It clearly states that account membership, access, and transferability are UNKNOWN and that this is not a transfer plan. Saving several rows sends one atomic request. A project revision or evidence/source change rejects the whole batch and refreshes the view. Work orders remain PLANNED; stock, reservations, and game state are not changed.

This workflow passed a synthetic disposable-SQLite browser scenario across three projects, including REST, AccountContext, and MCP reads. It checks separate source-intent and source-lead persistence, UI caveat wording, and exact commitment arithmetic. Server tests reject a lead on non-investigation work, a fabricated candidate, and a wrong-version assignee. A transaction test confirms both stale need evidence and source-screen leads cannot bypass current in-transaction review after a new import. It is not live-game validation.

## Phase 61 player workflow

Open **Projects & Work Orders** for an explicit version. Connect selected manual work to fully qualified prerequisite needs across projects. The portfolio panel groups each connected package, orders prerequisite steps first, and shows fresh observed coverage, missing or stale evidence, work-order readiness/progress, and both project-local reservation intent and overlapping source/resource commitments. Follow the links to review the specific project need. This is a review sequence, not an execution schedule; it does not claim reservation availability, action causation, route, recipe, ownership, or completion.

The synthetic browser acceptance uses three projects and a later import to exercise package ordering and evidence review through UI, REST, AccountContext, and MCP. Core tests also verify colliding local need IDs, version isolation, dangling references, UNKNOWN quantities, and overlapping reservations. No live-game or production validation was performed.
